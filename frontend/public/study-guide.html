Problem Statement & System Overview

Traditional job platforms are optimized for experienced hires. Fresh college graduates face distinct systemic challenges in the modern tech hiring landscape:

  • Experience Barrier: Entry-level filters often require 2–3 years of experience.
  • ATS Keyword Filtering: Applicant Tracking Systems eliminate resumes based on strict verbatim keyword matches, ignoring conceptual equivalence.
  • Zero Feedback Loop: Rejected applicants receive generic automated emails with no actionable guidance on which skills they lacked.
  • Unstructured Upskilling: Students must manually search multiple platforms to find relevant courses to close their skill deficits.
The CareerBridge Solution: CareerBridge replaces keyword filtering with an AI-driven hybrid matching engine, layout-aware PDF resume parsing, automated skill gap calculation, and targeted course recommendations.

AI/ML Recommendation Engine: Mathematical Deep Dive

CareerBridge uses a hybrid matching algorithm combining Natural Language Processing with discrete skill overlap.

1. TF-IDF (Term Frequency-Inverse Document Frequency)

Evaluates the importance of technical skills relative to the entire job corpus:

TF(t, d) = 1 + ln(count(t, d))
IDF(t, D) = ln((1 + |D|) / (1 + df(t))) + 1
TF-IDF(t, d, D) = TF(t, d) × IDF(t, D)

2. Cosine Similarity

Measures the cosine of the angle between student skill vectors and job requirements:

cos(θ) = (u · v) / (||u|| × ||v||) = ∑(u_i × v_i) / [ √∑(u_i²) × √∑(v_i²) ]

3. Hybrid Recommendation Scoring

Match_Score = [ 0.60 × Cosine_Similarity + 0.40 × (Matching_Skills / Required_Skills) ] × 100

This hybrid approach prevents candidates from matching purely on generic text while ensuring essential prerequisite skills are satisfied.

Resume Parsing & Skill Taxonomy

When a PDF resume is uploaded, pdfplumber extracts line-by-line text. The text is matched against an 88+ skill taxonomy using word-boundary regular expressions:

# Regex matching with word boundaries to prevent false positives
pattern = r"\b" + re.escape(skill_name.lower()) + r"\b"
if re.search(pattern, resume_text_lower):
    extracted_skills.append({'name': skill_name, 'category': category})

Extracted skills are automatically saved to the student profile, immediately recalculating job match scores.

Technical Viva & Interview Questions & Answers

Common questions asked in engineering project vivas and software interviews regarding this platform:

Q1: How does the AI job matching algorithm work?
It uses a hybrid algorithm: 60% TF-IDF Cosine Similarity (evaluating semantic alignment of student skill text and job descriptions with unigram/bigram tokens) and 40% Direct Skill Overlap (ensuring prerequisite skills are strictly present), producing a calibrated 0-100% score.
Q2: Why did you use TF-IDF rather than basic keyword search?
Keyword search only counts occurrences. A candidate who repeats "Python" 20 times would be favored over someone mentioning "Python, Docker, AWS". TF-IDF penalizes common words and applies sublinear scaling (1 + ln(count)), preventing keyword stuffing while highlighting specialized skills.
Q3: How does JWT authentication work and how are routes protected?
Flask-JWT-Extended issues an HMAC-SHA256 signed Bearer token containing user_id and role claims. React injects this into Axios requests. On the backend, @jwt_required() validates signatures, and a custom @admin_required decorator ensures only users with role === 'admin' can access sensitive admin endpoints.
Q4: How does the Skill Gap Analysis identify what skills to recommend?
For individual jobs, it computes the set difference: Required_Job_Skills \ Candidate_Skills. Across the platform, it evaluates the top 10 recommended jobs for the student and uses collections.Counter to rank missing skills by market frequency, prioritizing skills that unlock the most jobs.
Q5: Explain the database relationship between Users, Profiles, and Skills.
User has a 1-to-1 relationship with StudentProfile (user_id unique foreign key). StudentProfile has a Many-to-Many relationship with Skill implemented through the StudentSkill junction table, which also stores individual proficiency ratings (1-5).
